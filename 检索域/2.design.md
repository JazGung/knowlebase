## 1.2 领域类详情

### 1.2.1 SearchService

**字段映射**

| 字段名 | 存储映射 | 备注 |
| :--- | :--- | :--- |
| merge_strategy | - | 当前合并策略实例，由配置决定 |
| rerank_strategy | - | 当前重排序策略实例，由配置决定 |

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| search(query, version_id, top_n, debug) | SearchService.search() | 参数校验 → 并行召回 → 合并去重 → 补全信息 → 重排序 → 返回结果。debug=True 时保留各阶段中间结果 |
| _recall_es(query, version_id, top_n) | SearchService._recall_es() | 以 query 查询 ES 对应版本索引，过滤 stored=true 且 enabled=true，返回 [(chunk_id, score), ...]，上限 top_n × recall_ratio |
| _recall_milvus(query, version_id, top_n) | SearchService._recall_milvus() | 通过 /model/embedding 向量化 query → 查询 Milvus 对应版本 collection，过滤 enabled=true，返回 [(chunk_id, score), ...]，上限 top_n × recall_ratio |
| _recall_neo4j(query, version_id, top_n) | SearchService._recall_neo4j() | 通过 Higress 场景 entity-extract 抽取实体 → 查询 Neo4j 图谱，过滤 enabled=true，返回 [(chunk_id, score), ...]，上限 top_n × recall_ratio |
| _fill_metadata(db, version_id, candidates) | SearchService._fill_metadata() | 以 [(chunk_id, score), ...] 列表查询 PostgreSQL document_chunk JOIN document JOIN document_version_relation，按 version_id 过滤且 stored=true，返回 [SearchResultItem, ...] |

### 1.2.2 MergeStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| merge(path_results, weights) | MergeStrategy.merge() | 接收三路 [(chunk_id, score), ...] 列表及各路权重，按策略计算合并分数，去重后返回 [(chunk_id, merged_score), ...] 按分数降序排列 |

### 1.2.3 RRFMergeStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| merge(path_results, weights) | RRFMergeStrategy.merge() | 对每条结果的 rank 计算加权 RRF 分数：`Σ w_i / (k + rank_i)`，k 为平滑常数（默认 60），按分数降序返回 |

### 1.2.4 WeightedNormalizationMergeStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| merge(path_results, weights) | WeightedNormalizationMergeStrategy.merge() | 对各路分数做 min-max 归一化，乘以对应权重求和：`Σ w_i × norm_i`，按分数降序返回 |

### 1.2.5 RerankStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| rerank(items, query, top_k) | RerankStrategy.rerank() | 接收 [SearchResultItem, ...] 列表、原始 query、返回条数 top_k，重排序后返回 top_k 条 |

### 1.2.6 CrossEncoderRerankStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| rerank(items, query, top_k) | CrossEncoderRerankStrategy.rerank() | 以 (query, chunk_text) 对送入 Cross Encoder 模型打分，按分数降序返回 top_k 条 |

### 1.2.7 LLMRerankStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| rerank(items, query, top_k) | LLMRerankStrategy.rerank() | 通过 Higress 场景 rerank 调用 LLM 对候选列表精排，返回 top_k 条 |

### 1.2.8 NoopRerankStrategy

**内部方法说明**

| 方法 | 入口 | 流程 |
| :--- | :--- | :--- |
| rerank(items, query, top_k) | NoopRerankStrategy.rerank() | 直接截取前 top_k 条返回，不做重排序 |

# 2. 数据结构

检索域无自有持久化表，读取以下业务资源域表：

- `document_chunk`：分块文本（processed_text）、页码（page_range_start / page_range_end）、章节标题（section_title）
- `document`：文档名称（file_name）
- `knowledge_base_version`：版本列表、版本状态

检索域读取以下构建域写入的存储层（schema 以构建域 DEG §4.4.8 为权威来源）：

- Elasticsearch：分块全文索引，包含 chunk_id、document_id、version_id、stored、enabled
- Milvus：分块向量，包含 chunk_id、document_id、version_id、enabled
- Neo4j：实体-关系-实体三元组，实体节点和关系边均包含 chunk_id、enabled

## 4.4 检索 API

**对应 REQ 章节**：无页面需求 → 检索 API

**请求模型**: `retrieval.schema.SearchRequest`

| 字段 | 类型 | 必填 | 校验规则 |
| :--- | :--- | :--- | :--- |
| query | str | M | 非空，最大 2000 字符 |
| top_n | int | O | 正整数，未传时取默认值 `SEARCH_RESULTS_LIMIT` |

**响应模型**: `retrieval.schema.SearchResponse`

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| results | List[ChunkTextItem] | 最终匹配的分块文本列表 |

**ChunkTextItem**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| chunk_text | str | 分块处理后的文本 |

### 4.4.1 处理流程

1) 校验 query 非空、top_n（若传入）为正整数
2) 查询 knowledge_base_version 表获取 status='enabled' 的记录，不存在则抛出 `RETRIEVAL_NO_ENABLED_VERSION`
3) 以已启用版本 ID 调用 SearchService.search(query, version_id, top_n, debug=False)
4) 从重排序后结果中截取 top_n 条的 chunk_text，组装返回

### 4.4.2 SearchService.search()

**输入**：query、version_id、top_n、debug

**处理流程**

1) 权重归一化：读取 SEARCH_KEYWORD_WEIGHT / SEARCH_SEMANTIC_WEIGHT / SEARCH_GRAPH_WEIGHT，除以三者之和
2) 并行召回：asyncio.gather 执行三路召回（权重为 0 的路径跳过），各路返回上限 = int(top_n × SEARCH_RECALL_RATIO) 条 [(chunk_id, score), ...]
3) 合并去重：调用 merge_strategy.merge()，取 top_n × SEARCH_MERGE_RATIO 条
4) 补全信息：按 chunk_id 列表查询 PostgreSQL document_chunk JOIN document，过滤 stored=true 且 enabled=true，填充 SearchResultItem
5) 重排序：调用 rerank_strategy.rerank()，取 top_n 条
6) 返回 SearchResult

**中间结果**：`SearchResult`

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| es_results | List[SearchResultItem] | ES 召回原始结果（debug 模式） |
| milvus_results | List[SearchResultItem] | Milvus 召回原始结果（debug 模式） |
| neo4j_results | List[SearchResultItem] | Neo4j 召回原始结果（debug 模式） |
| merged_results | List[SearchResultItem] | 合并去重后结果（debug 模式） |
| reranked_results | List[SearchResultItem] | 重排序后最终结果 |
| SearchResultItem | — | 单条检索结果 |

**SearchResultItem**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| chunk_text | str | 分块文本（document_chunk.processed_text） |
| document_name | str | 所属文档名称（document.file_name） |
| page_number | int | 所在页码（document_chunk.page_range_start） |
| chapter_title | str | 所在章节标题（document_chunk.section_title） |
| score | float | 相关性分数 |

### 4.4.3 并行召回 — ES

**输入**：query、version_id、top_n × recall_ratio

**处理流程**

1) 以 query 构造 ES 全文检索查询，过滤条件：version_id、stored=true、enabled=true
2) 执行检索，返回 (chunk_id, score) 列表，上限为 top_n × recall_ratio

### 4.4.4 并行召回 — Milvus

**输入**：query、version_id、top_n × recall_ratio

**处理流程**

1) 调用 /model/embedding（通过 Higress 场景 embedding）将 query 向量化
2) 以向量查询 Milvus 对应 collection，过滤条件：enabled=true，表达式含 version_id
3) 返回 (chunk_id, score) 列表，上限为 top_n × recall_ratio

### 4.4.5 并行召回 — Neo4j

**输入**：query、version_id、top_n × recall_ratio

**处理流程**

1) 调用 LLM 抽取 query 中的实体（通过 Higress 场景 entity-extract）
2) 以抽取的实体查询 Neo4j 图谱，匹配实体节点后沿关系边遍历获取关联 chunk_id，过滤条件：enabled=true
3) 返回 (chunk_id, score) 列表，上限为 top_n × recall_ratio

### 4.4.6 合并去重

**输入**：三路 [(chunk_id, score), ...] 列表

**处理流程**

1) 各路权重归一化（若三路权重和为 0，已在启动时校验拦截）
2) 调用当前 merge_strategy.merge(path_results, normalized_weights)
3) 按 chunk_id 去重，同一 chunk_id 保留最高分
4) 按合并分数降序排列，截取 top_n × SEARCH_MERGE_RATIO 条
5) 返回 [(chunk_id, merged_score), ...]

### 4.4.7 补全信息

**输入**：[(chunk_id, merged_score), ...]

**处理流程**

1) 提取 chunk_id 列表
2) 查询 PostgreSQL：
   - document_chunk JOIN document ON document_chunk.document_id = document.id
   - 条件：chunk_id IN (...)、stored=true、enabled=true
   - 字段：processed_text、page_range_start、section_title、file_name
3) 映射为 SearchResultItem 列表，保留 merged_score 作为 score

### 4.4.8 重排序

**输入**：[SearchResultItem, ...]（top_n × SEARCH_MERGE_RATIO 条）、query、top_n

**处理流程**

1) 调用当前 rerank_strategy.rerank(items, query, top_n)
2) 返回 top_n 条 SearchResultItem

### 4.4.9 运行配置

#### 检索参数

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `SEARCH_RESULTS_LIMIT` | int | `20` | 默认最终返回条数，API 参数未指定 top_n 时使用 |
| `SEARCH_KEYWORD_WEIGHT` | float | `0.4` | ES 全文检索权重，归一化后应用，设为 0 则跳过该路 |
| `SEARCH_SEMANTIC_WEIGHT` | float | `0.4` | Milvus 语义检索权重，归一化后应用，设为 0 则跳过该路 |
| `SEARCH_GRAPH_WEIGHT` | float | `0.2` | Neo4j 图谱检索权重，归一化后应用，设为 0 则跳过该路 |
| `SEARCH_RECALL_RATIO` | float | `3.0` | 各路召回增幅比例，每路返回 top_n × recall_ratio 条。须 ≥ 1.0 |
| `SEARCH_MERGE_RATIO` | float | `2.0` | 合并后送入重排序的增幅比例，取 top_n × merge_ratio 条。须 ≥ 1.0 |
| `SEARCH_MERGE_STRATEGY` | str | `rrf` | 合并策略。可选值：`rrf`（倒数秩融合）、`weighted_normalization`（分数归一化加权） |
| `SEARCH_RERANK_STRATEGY` | str | `cross_encoder` | 重排序策略。可选值：`cross_encoder`、`llm`、`none`（跳过重排序） |

#### 启动校验

启动时调用 `validate_search_config()`，以下任一项不满足则抛出 `ValueError` 终止启动：
- `SEARCH_KEYWORD_WEIGHT`、`SEARCH_SEMANTIC_WEIGHT`、`SEARCH_GRAPH_WEIGHT` 均须 ≥ 0，存在负值则报错终止
- 三者不能全为 0，全 0 则报错终止
- `SEARCH_RECALL_RATIO`、`SEARCH_MERGE_RATIO` 均须 ≥ 1.0，不满足则报错终止
- `SEARCH_MERGE_STRATEGY` 须为 `rrf` 或 `weighted_normalization`，否则报错终止
- `SEARCH_RERANK_STRATEGY` 须为 `cross_encoder`、`llm` 或 `none`，否则报错终止

## 4.5 检索调试

**对应 REQ 章节**：数据查询 → 检索调试

**请求模型**: `retrieval.schema.DebugSearchRequest`

| 字段 | 类型 | 必填 | 校验规则 |
| :--- | :--- | :--- | :--- |
| query | str | M | 非空，最大 2000 字符 |
| version_id | int | M | 存在的知识库版本 ID |
| top_n | int | O | 正整数，未传时取默认值 `SEARCH_RESULTS_LIMIT` |

**响应模型**: `retrieval.schema.DebugSearchResponse`

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| es_results | List[SearchResultItem] | ES 全文检索原始命中列表 |
| milvus_results | List[SearchResultItem] | Milvus 语义检索原始命中列表 |
| neo4j_results | List[SearchResultItem] | Neo4j 图谱检索原始命中列表 |
| merged_results | List[SearchResultItem] | 合并去重后结果 |
| reranked_results | List[SearchResultItem] | 重排序后最终结果 |

### 4.5.1 处理流程

1) 校验 query 非空、version_id 存在
2) 校验 knowledge_base_version 状态为 succeeded / enabled / disabled（已构建完成），不满足则抛出 `RETRIEVAL_VERSION_NOT_BUILT`
3) 调用 SearchService.search(query, version_id, top_n, debug=True)
4) 组装 5 部分结果返回

## 4.6 可用版本列表

**对应 REQ 章节**：数据查询 → 检索调试（版本下拉框数据来源）

**响应模型**: `retrieval.schema.VersionListResponse`

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| versions | List[VersionOption] | 可选版本列表 |

**VersionOption**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | int | 版本 ID |
| version_name | str | 版本名称 |
| version_code | int | 版本编码（毫秒时间戳） |
| status | str | 版本状态 |
| is_built | bool | 是否已构建（status 为 succeeded / enabled / disabled），供前端确定可选范围 |

### 4.6.1 处理流程

1) 查询 knowledge_base_version 表，status 为 succeeded / enabled / disabled / failed 的记录（排除 init 和 building）
2) 按 version_code 降序排列
3) 映射为 VersionOption 列表，stored=failed 时 is_built=false
